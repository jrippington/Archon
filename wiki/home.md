# Archon Wiki

Archon is a .NET architecture-intelligence platform. The current foundation provides independently runnable API and MCP hosts, Aspire-based local composition, a domain model for deterministic architecture graph facts, a Neo4j persistence foundation for storing assembled snapshots, and the first asynchronous API extraction workflow. That workflow validates explicit repository and solution inputs, records operational run state, dispatches repository, solution, supported C# or VB.NET project metadata, project-reference extraction, analyzer extraction, FilePath artifact extraction, package-reference extraction, legacy `packages.config` extraction, application type classification, Roslyn semantic extraction, WP007 configuration/dependency-injection extraction, WP008 runtime extraction, and WP009 LINQ to SQL, Entity Framework, ADO.NET, and typed DataSet data-access extraction through an application orchestrator, assembles a generalized snapshot, hands it to the configured persistence writer, and exposes status plus recent history through API endpoints. The runtime extraction slice currently covers ASP.NET Core endpoint/controller/pipeline facts, classic ASP.NET runtime artifacts, C# or VB.NET console entry-point facts, worker hosted-service facts, and non-HTTP scheduled-job or message-consumer facts. The data-access slice currently covers static LINQ to SQL `.dbml` model facts for DataContexts, entities, tables, columns, associations, and stored procedures; EF6 and EF Core source facts for DbContexts, ObjectContexts, DbSets, mappings, migrations, providers, raw SQL, saves, and usage relationships; ADO.NET command facts for raw SQL, stored procedures, affected table hints, read/write hints, dynamic SQL unknowns, provider hints, and redacted evidence; and typed DataSet `.xsd`, generated source, TableAdapter, query, stored procedure, usage, evidence, and unknown facts. The Roslyn layer contains compiler-backed C# and VB.NET declaration, relationship, diagnostic, unknown, generated-code, partial-declaration, metadata-symbol extraction, and snapshot projection behavior. Query APIs, MCP graph tools, markdown export, and user-interface behavior remain assigned to later work packages.

This wiki is the contributor-facing source of truth for current behavior, terminology, validation workflows, and repository operating model. Work-package specs and plans under `docs/` explain how work is planned and recorded; the wiki explains how contributors should understand and work with the repository now.

## Current capability summary

The API host and MCP host expose operational probes. The API host also maps the extraction workflow endpoints: `POST /extractions` accepts validated repository and solution inputs, creates queued operational run state, schedules asynchronous orchestration, and `GET /extractions/{runId}` plus `GET /extractions` expose current status and recent run history. The Aspire AppHost composes Neo4j, `ArchonApi`, and `ArchonMcp` for local development and intentionally does not compose a Discovery UI resource. The graph domain model defines stable vocabulary and contracts for architecture facts, while the Neo4j infrastructure adapter persists supplied graph contracts after schema initialization. The current extraction workflow persists repository nodes, solution nodes, supported C# and VB.NET project nodes with application type metadata, package nodes, FilePath nodes, repository-to-solution containment relationships, solution-to-project containment relationships, project-to-project `REFERENCES` relationships from `ProjectReference` declarations, project-to-package `USES_PACKAGE` relationships from SDK-style `PackageReference` and legacy `packages.config` declarations, solution-file evidence, project-declaration evidence, project-file evidence, project-reference evidence, analyzer-reference evidence, and package-reference evidence for explicitly submitted solutions and repository-contained dependency targets. The Roslyn semantic stage also persists C# and VB.NET declaration nodes, compiler-resolved relationship edges, compiler-symbol evidence, compiler-diagnostic evidence, non-blocking semantic unknown warnings, generated-code classification, partial declaration evidence contributions, and metadata-only symbol dependencies through the same API orchestration and snapshot writer seam. The WP007 stage persists Microsoft DI registration facts, registration wrappers, constructor correlation, legacy container facts, service-locator and manual-factory heuristics, modern appsettings parsing, options binding, configuration key nodes, `USES_CONFIG` relationships, redacted evidence, and controlled warnings. The WP008 runtime stage persists ASP.NET Core endpoint/controller/pipeline facts, classic ASP.NET runtime artifacts, C# or VB.NET console entry-point facts, worker hosted-service facts, scheduled-job facts, queue/topic consumer facts, message-handler facts, service-host metadata, and custom host-loop facts through that same API orchestration and snapshot writer seam. The WP009 data-access stage persists LINQ to SQL DBML `DataContext`, EF `DbContext` and `ObjectContext`, ADO.NET command usage, typed DataSet model usage, entity, database table, database column, association, stored-procedure, migration artifact, generated TableAdapter artifact, raw SQL, provider, SQL preview/hash, affected table hint, `MAPS_ENTITY`, `MAPS_TABLE`, `MAPS_COLUMN`, `USES_DB_CONTEXT`, `USES_LINQ_TO_SQL_CONTEXT`, `READS_TABLE`, `WRITES_TABLE`, `CALLS_STORED_PROCEDURE`, `REFERENCES`, and `EXECUTES_RAW_SQL` facts with redacted evidence and explicit unknowns for partial model identity, partial typed DataSet metadata, convention-only mappings, shadow properties, unresolved targets, computed SQL, and missing command text. No query API, MCP graph access behavior, markdown export, or user-interface behavior is complete yet.
