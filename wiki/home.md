# Archon Wiki

Archon is a .NET architecture-intelligence platform. The current foundation provides independently runnable API and MCP hosts, Aspire-based local composition, a domain model for deterministic architecture graph facts, a Neo4j persistence foundation for storing assembled snapshots, a copied-output JSON rule catalog loader, and the first asynchronous API extraction workflow. That workflow validates explicit repository and solution inputs, records operational run state, dispatches repository, solution, supported C# or VB.NET project metadata, project-reference extraction, analyzer extraction, FilePath artifact extraction, package-reference extraction, legacy `packages.config` extraction, application type classification, Roslyn semantic extraction, WP007 configuration/dependency-injection extraction, WP008 runtime extraction, WP009 LINQ to SQL, Entity Framework, ADO.NET, and typed DataSet data-access extraction, WP010 external integration extraction, WP011 UI/client extraction, WP012 rule catalog persistence/evaluation, and WP013 metrics slices through an application orchestrator, assembles a generalized snapshot, hands it to the configured persistence writer, and exposes status plus recent history through API endpoints. The rule catalog slice currently loads repository-authored JSON rule files from copied runtime output, validates their schema-equivalent and semantic shape, includes first-cut built-in rules for lifecycle, legacy technology, data-access, obsolete API, security-sensitive, configuration, dependency-risk, modernization-blocker, and architecture-smell scenarios, upserts versioned Neo4j catalog records by rule code and version, evaluates enabled rules over accumulated graph facts, constructs deterministic findings with history and suppression fields, exposes controlled rule catalog, hotlist, finding detail, finding history, and suppression API behavior, and exposes deterministic diagnostics for invalid catalog or partial evaluation content. WP013 currently calculates and persists snapshot, project, graph, and modernization metrics as snapshot-owned `metric://` outputs with stable identity, fingerprint, confidence, unknown-state fields, and controlled query API access; it also exposes query-side dependency cycle detection, architecture hotspots, generic architecture-rule results, and snapshot diff comparison through stable public DTOs. WP014 currently exposes dashboard summary, project catalogue, project detail, direct dependency, direct dependent, transitive dependency, transitive dependent, dependency path, graph-neighbourhood, symbol search, symbol detail, symbol usage, runtime endpoint, runtime controller/handler, runtime entry-point, runtime worker, data-access fact, configuration usage, integration fact, UI-technology fact, evidence detail, related-evidence, rule catalog, finding/hotlist, snapshot metric, snapshot hotspot, architecture-rule result, dependency-cycle, explicit snapshot diff, latest-to-previous snapshot diff, cross-domain search, repository registration, solution registration, constrained metadata management, snapshot lifecycle, retention, extraction run history, rule enablement, controlled maintenance, health, and readiness API behavior over resolved repository, solution, snapshot, and management scope with stable public identities, controlled filters, bounded paging or traversal limits, warnings, unknowns, evidence references, audit-ready metadata, deterministic follow-up affordances, truncation metadata, bounded snippet previews, secret-safe metadata, and safe error shapes. The runtime extraction slice currently covers ASP.NET Core endpoint/controller/pipeline facts, classic ASP.NET runtime artifacts, C# or VB.NET console entry-point facts, worker hosted-service facts, and non-HTTP scheduled-job or message-consumer facts. The data-access slice currently covers static LINQ to SQL `.dbml` model facts for DataContexts, entities, tables, columns, associations, and stored procedures; EF6 and EF Core source facts for DbContexts, ObjectContexts, DbSets, mappings, migrations, providers, raw SQL, saves, and usage relationships; ADO.NET command facts for raw SQL, stored procedures, affected table hints, read/write hints, dynamic SQL unknowns, provider hints, and redacted evidence; and typed DataSet `.xsd`, generated source, TableAdapter, query, stored procedure, usage, evidence, and unknown facts. The external integration slice currently contributes the safe pipeline seam, graph-projection contracts, deterministic stable-key helpers, and no-live-call boundary plus source-analysis detectors for HTTP, REST, WCF, SOAP, gRPC, messaging, storage, SMTP/email, payment, and internal service API dependencies. The UI extraction slice currently contributes static Blazor, Razor Pages, MVC Razor, Windows Forms, WPF, WinUI, .NET MAUI, and Avalonia facts with repository-relative evidence, redacted snippet previews, confidence, warnings, and explicit unknowns without rendering UI or starting target applications. The Roslyn layer contains compiler-backed C# and VB.NET declaration, relationship, diagnostic, unknown, generated-code, partial-declaration, metadata-symbol extraction, and snapshot projection behavior. The MCP host now exposes the read-only WP015 tools, resources, and prompts over approved application/query abstractions; markdown export is intentionally deferred until Discovery UI direction and information architecture are clearer, and product user-interface behavior remains outside the current implementation sequence.

This wiki is the contributor-facing source of truth for current behavior, terminology, validation workflows, and repository operating model. Work-package specs and plans under `docs/` explain how work is planned and recorded; the wiki explains how contributors should understand and work with the repository now.
